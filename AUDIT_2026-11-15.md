## Open findings

### Signing core and bridge

- **S1 High, extension with an explicit profile fails verification.** `ProvisioningAudit.swift:334-358` gives an extension with no profile of its own the app's profile, and the row text says it "will sign this app extension". zsign keeps the app's asset for `.appex` (`bundle.cpp:365-375`), so the extension embeds the app's profile. The verifier in `Bridge/zsign_wrapper.cpp` (profile match, around line 896) requires the embedded profile to match every non-root bundle. `com.app.ext` does not match `TEAM.com.app`, so verification fails and `SigningRequest.swift:85` removes the partial file. It fails closed, so no bad IPA reaches the Library. But the 2.8.4 release claim that extensions sign again is true only for wildcard profiles. **Fix:** let the verifier accept the root profile for `.appex`, or block such extensions in the audit, and add a test that signs with an explicit profile.
- **S2 Medium, output verification is structural.** `archo.cpp:286-294` treats a non-empty signature blob as signed. The only seal check is that `_CodeSignature/CodeResources` exists. No hashes are recomputed, the signer is not compared with the profile's certificates, and the signed bundle ID is not compared with the requested one. A broken seal would pass. **Fix:** recompute the CodeResources and code-directory hashes (or run zsign's own check) before promoting, and compare the bundle ID and signer.
- **S3 Medium, "authentic" means CMS integrity, not Apple issuance.** `zsign_wrapper.cpp:1061` calls `CMS_verify` with `CMS_NO_SIGNER_CERT_VERIFY` and no trust store. `ProfileStore.swift:178-211` sets `profileIsAuthentic = true`, and the audit blocks on that flag only. A self-signed profile is labelled authentic. iOS is still the real gate at install. **Fix:** validate the signer chain to Apple's roots, or relabel the flag as "structure valid".
- **S4 Medium, a failed index decode is treated as empty, and the next save overwrites it (verified).** `HistoryStore.swift:200-210`: `load()` returns with empty records on any decode error, and `save()` then writes the whole array over `history.json`. The same pattern appears in `ProfileStore.swift:251-264, 317-322`, `CertificateStore.swift:197-210` and `RefreshPlanner.swift:162-163, 270-273`. A schema change or downgrade followed by any append permanently drops the index, and certificate passwords become unreachable Keychain entries. Orphaned refresh sources are not counted in `totalBytes`, so the 1.5 GB budget is not enforced. **Fix:** on decode failure, move the file aside (for example `history.json.bad-<date>`) and refuse to save over it. **Priority:** fix this before S1.
- **S5 Low, declared zip sizes and plist reads are not enforced.** `archive.cpp:260` writes until the decompressor ends, and nothing compares the byte count with the declared size. The 8 GiB and ratio checks use header values only. `zsign_wrapper.cpp:28` loads a whole extracted plist or profile with no cap. **Fix:** count bytes in `_ReadFileFromZip` and abort past the declared size; cap plist reads at a few MB.
- **S6 Low, fixed buffers truncate silently.** `zsign_wrapper.cpp:391` writes the version into a 128-byte buffer. `zsign_wrapper.cpp:44` reads plist values into `char tmp[1024]`, so a longer value becomes `""` and the bundle is dropped from inspection and the audit (`:126`). **Fix:** check the `snprintf` return and fail; size buffers from the value.
- **S7 Low, two audit checks skip silently when data is missing.** Device membership is skipped when `ALTDeviceID` is absent (`ProvisioningAudit.swift:247-255`, `currentDeviceIdentifier` at `:163-172`), and the "cannot be confirmed" warning only appears when a device ID exists (`:278-281`). The fingerprint check is skipped when `DeveloperCertificates` is empty (`:239-246`). The row still reads "ready". **Fix:** warn or block when either input is missing.
- **S8 Low, P12 password and certificate-file lifetime.** Passwords are cached as plain strings for the life of the process (`CertificateStore.swift:31, 56-65`) and are not cleared on lock or background. `PasswordVault.save` deletes the existing Keychain item before adding the new one (`~225`), so a failed add loses the saved password. P12 and profile copies go to the temporary directory (`CertificateStore.swift:156-163`, `ProfileStore.swift:226-233`) and are never swept at launch. **Fix:** clear the cache on background and lock; add the new item before deleting the old one; sweep temp copies at launch.
- **S9 Low (partly fixed), the signing log keeps more than it needs and is unprotected.** The entitlements dump is fixed (see above). Still present: the team and subject common name are printed (`bundle.cpp:1061-1062`), and the IPA name and profile names are recorded. `ForgeLog` writes without file protection and is backed up by default. **Fix:** write with `.completeFileProtection`, and mark `signing.log` as excluded from backup.
- **S10 Info, log capture is not synchronised.** `log.cpp` and `zsign_wrapper.cpp` have no lock on the capture buffer. It is safe today only because every zsign call runs on the signing serial queue. Output from `validateSigningAsset` (`SigningRequest.swift:~89`) is not captured, so a certificate or profile mismatch logs "no output".
- **S11 Info, sign-time safety depends on the caller.** The worker re-checks only the certificate and profile pairing. Bundle coverage, expiry, team, device and App Group checks happen in the ContentView audit before the request is built. The background metadata refresh can change `profileIsAuthentic` after the audit. **Fix:** re-run the audit inside the worker, or pass its result in the request.

### Network, install and Apple account

- **N1 Medium, the install manifest is validated but not what iOS installs.** ForgeSign fetches and checks the manifest from `api.palera.in`, then iOS fetches its own copy through the `itms-services` link (`InstallController.swift:150-181`). The check does not bind the install. The host also receives the bundle ID, app name, version and loopback port on every install (`LocalInstallServer.swift:121-131`). **Fix:** document `api.palera.in` as a trust dependency or host the manifest yourself; do not present the check as an integrity guarantee.
- **N2 Medium, remote anisette is on by default and sends identifiers without per-server consent (verified).** The default mode `.automatic` (`AnisettePreference.swift:42`) sends the persistent device identifier and the provisioning exchange to the first three community servers. The provisioning blob is stored under one global Keychain account, so a blob from server A is posted to server B later (`RemoteAnisetteService.swift:330-342`). **Fix:** make remote servers opt-in with per-server disclosure, and key the stored blob by server.
- **N3 Medium (Low if ATS blocks it), plain HTTP is accepted for custom anisette.** `AnisettePreference.swift:74-82` and `RemoteAnisetteService.swift:27-45` accept `http://`, so identifiers and tokens can travel unencrypted. The AltServer fallback fetches `http://<peer>:6969` (`AltServerClient.swift:203-205, 255-261`). ATS allows only local networking; not confirmed whether it covers IP-literal LAN hosts. **Fix:** require HTTPS for custom and remote servers; allow HTTP only for the AltServer fallback, with a visible warning.
- **N4 Medium, unbounded in-memory response for anisette.** `AnisetteSupport.swift:211-218` and `RemoteAnisetteService.swift:620-637` buffer the whole body with no byte cap. The resource timeout is the 7-day default, and the 12 s inactivity timer can be kept alive by a peer that trickles bytes. **Fix:** stream the body and stop past about 1 MB; set a resource timeout.
- **N5 Medium, the download budget is 2 GB during transfer (verified).** `BoundedTransfer.swift:176` checks against `maximumBytes` (2 GB), not the catalog's declared size. The declared size is compared only at completion (`:203`), so a catalog declaring 1 MB can write up to 2 GB first. There is no free-space check. **Fix:** use `min(maximumBytes, expectedBytes)` as a hard cap during transfer, and check free space before starting.
- **N6 Low, the first Bonjour AltServer is chosen without asking.** `AltServerClient.swift:182-184, 340`. The connection is plain TCP with no authentication. The Apple password is not sent to it. **Fix:** let the user choose the server and see its name and address.
- **N7 Low (verified), Apple ID and UDID in plaintext defaults; password kept in memory.** The Apple ID and device UDID are stored with `@AppStorage` (`ContentView.swift:51-52, 59`), which writes to a plaintext plist that is included in backups. The Apple password is held in `@State` and never cleared after provisioning. **Fix:** store the Apple ID in the Keychain, and clear the password once provisioning returns.
- **N8 Low (loopback verified), the install server has no per-install token.** The server binds to `127.0.0.1` only (`LocalInstallServer.swift:159`), so LAN exposure is not possible. But `/app.ipa` needs no token, so any process on the same device that finds the port can fetch the signed IPA during the install window. `SO_RCVTIMEO` applies per receive, not to the whole request, and connections are not capped (`:245, 266-274, 103-107, 301-307`). **Fix:** put a random per-install token in the path, add an overall header deadline, and cap concurrent connections at about 4.
- **N9 Low, the host blocklist is a literal match.** `NetworkPolicy.swift:32-33` blocks only `localhost`, `127.0.0.1` and `::1`. Catalog URLs and redirects can reach other private and link-local ranges over HTTPS (`BoundedTransfer.swift:144`, `RepositoryStore.swift:315, 362-364`). Responses are not returned to the attacker, so impact is limited. **Fix:** resolve the host and reject private and link-local addresses, or stop claiming the blocklist protects local networks.
- **N10 Low, the 2FA prompt has no timeout or cancellation.** The AltSign continuation (`AltServerProvisioningService.swift:249-281`) has no timeout, and the task started at `ContentView.swift:~886` is not stored. `signer.phase` stays `.provisioning` until the alert is answered. **Fix:** store the task, wrap the continuation in a cancellation handler, and add a timeout that calls `cancelVerification()`.
- **N11 Low, misleading network messages.** A manifest that fails validation is reported as "Remote manifest server unavailable" (`InstallController.swift:153-161, 187`). Raw `NSError` text reaches the user (`RepositoryStore.swift:376-381`). The catalog is read one byte at a time (`for try await byte in bytes`), which is slow for a 25 MB catalog. **Fix:** give validation failures their own message, map POSIX errors to plain text, and read in chunks.
- **N12 Info (verified), `SecItemAdd` results are ignored.** `AltServerProvisioningService.swift:626` and `RemoteAnisetteService.swift:254`. If the write fails, the team certificate is not saved and the device identity is regenerated on each call. **Fix:** check the status and show an error.
- **N13 Info, inconsistent client identity.** The patched GSA requests claim to be Xcode (`vendor/altsign-gsa-http503.patch`, `X-Xcode-Version`), while the anisette code says the identity must be `akd`. **Fix:** choose one identity that matches the anisette data, and document it.

### SwiftUI state, accessibility and copy

- **U2 Medium, the Apple provisioning warning stays above a successful result.** `ContentView.swift:828` clears it only in one branch, and the fallback at `:949-952` does not. **Fix:** clear it on success.

- **U4 Medium, the preflight card is not refreshed when Apple account settings change (verified).** The `onChange` list (`ContentView.swift:229-240`) has no handler for the Apple ID, the password or the anisette URL, so the card can show a device verdict from the previous account. `sign()` recomputes the audit, so only the card is wrong. **Fix:** add handlers for those three values.
- **U5 Medium, GET buttons are unlabelled, small and unexplained when disabled.** `SourcesView.swift:364-378`. VoiceOver reads "GET" for every row, the capsule is about 26 pt tall, and it is disabled with no reason when there is no download link. **Fix:** add an accessibility label with the app name, a 44 pt minimum height, and a "No download link" line.
- **U6 Medium, icon-only hit areas are about 15 pt.** `AutomaticProvisioningSection.swift:147-159, 201-209`. **Fix:** a 44 pt frame with `contentShape`.
- **U7 Medium, the discovery error is cut to one line.** `AutomaticProvisioningSection.swift:228-233`. **Fix:** let it wrap, as the anisette result beside it does.
- **U8 Medium, a repository fetch failure has no retry and no status code.** `SourcesView.swift:255-258`; `RepositoryStore.swift:291`. The only recovery is pull-to-refresh, which nothing advertises. **Fix:** add a Retry button and include the HTTP status.
- **U9 Medium, the "action needed" pill does not say what to do.** `LibraryView.swift:259-262`, with the dialog at `:66-74`, which also omits refresh. **Fix:** name the action ("Re-sign from the original IPA") and explain it in the dialog.
- **U12 Medium, the import alert may not show over the closing picker (needs device check).** `ContentView.swift:179-198`. `importError` is set in the same pass that starts dismissing the picker. **Fix:** set the message in the sheet's `onDismiss`.
- **U13 Low, a blank Continue cancels sign-in silently.** `ContentView.swift:208`; `AltServerProvisioningService.swift:108-115`. An empty field sends `nil`, the same as Cancel. **Fix:** disable Continue until there is input.
- **U14 Low, picker failures are dropped.** `CertificatesSheet.swift:76` and `ProfilesSheet.swift:70` ignore `.failure`. **Fix:** set the error.
- **U15 Low, "Signing…" shows during the kept-original copy.** The signed IPA appears late (`ContentView.swift:860-867`). **Fix:** set `.done` and `signedIPA` before the copy.
- **U16 Low, light-mode status colours are below AA for 9 pt text.** `ForgeTheme.swift:92-93` for `good` and `warn` is about 4.2–4.3:1 on white, used at 9 pt in `GlassStatusPill` (`ForgeComponents.swift:337`). The dark tokens are above 7:1. **Fix:** darken the light values by about 10%.
- **U17 Low, text buttons are about 41–42 pt tall.** `DylibInjectionSection.swift:39-53`, `LibraryStorageView.swift:162-178`. **Fix:** `minHeight: 44`.
- **U18 Low, copy that is wrong or cannot be acted on.** `ContentView.swift:628` says ForgeSign "will sign" while the audit may block. `ContentView.swift:802`: "it will not be installed" has no clear subject. `ForgeComponents.swift:247`: "Double-tap to choose a file" also applies to certificate and profile rows, which open sheets. `P12Inspector.swift:112` says "expired 3d" while `RefreshPlanner.swift:91` says "Expired 3d ago". `LibraryView.swift:85-88`: "Could not delete signed IPA" also covers "Remove from Library". `SigningLogView.swift:14`: "Nothing has been signed on this device yet" also shows after Clear. **Fix:** name the object and the action in each.

### Build, CI and docs

- **B1 High (verified), a tag run can overwrite a published release.** `.github/workflows/ios.yml:128-129, 146-147`. When the release exists, the job runs `gh release upload --clobber`, which replaces the versioned IPA, `ForgeSign-latest.ipa` and `SHA256SUMS.txt`. The only check that the release points at the built commit (`:134-139`) runs for manual dispatch only. Pushing a moved tag re-runs the workflow and silently swaps the binary and its checksums. **Fix:** when the release exists, fail unless its target commit equals `$GITHUB_SHA`; never `--clobber` a published release.
- **B2 Medium (verified), the manual-run guard fails open.** `ios.yml:134-139`: `if EXISTING=$(gh api … 2>/dev/null)` skips the check on any error (auth, rate limit, outage) and carries on to `--clobber`. **Fix:** fail on anything except a 404, and refuse to replace assets whose checksum differs.
- **B3 Medium (verified), the formatting check checks nothing committed.** `ios.yml:48-49` runs `git diff --check` with no arguments, which compares the index with the working tree. On a clean checkout that is empty, so the step passes whatever is committed. **Fix:** `git diff --check origin/main...HEAD` with `fetch-depth: 0`.
- **B4 High, CI never exercises real signing.** The test host `ForgeSignUISim` is built without `FORGE_BRIDGE`, so `SigningService.sign` returns "Signing engine unavailable". No test calls `sign()`. The bridge probe has no assertions and CI never runs it. Dylib injection and verification are untested in CI. **Fix:** add a CI step that signs a fixture IPA with a generated self-signed P12 and validates the output. Until then, list signing as untested.
- **B5 Low (verified), the test count in the docs is stale.** `docs/index.html:555` says "85 simulator tests in CI". `README.md:146` and `WHATS_NEW.md` say 86 in 8 suites. The run now reports 89 tests in 9 suites, including the new Signing log suite and the parameterised cases. **Fix:** update the page, and state whether a count is declared or taken from a run.
- **B6 Low, a pipeline inversion in the IPA check.** `ios.yml:99`: `! unzip -Z1 … | grep -E` passes if `unzip` itself fails. Nothing rejects `*.debug.dylib` or `*.preview.dylib` in `validate_ipa` (`scripts/package_ipa.py:16-51`), and no test covers it. Mitigated by `ENABLE_DEBUG_DYLIB: NO`. **Fix:** capture the listing into a variable and grep it; add the rejection to `validate_ipa` with a test.
- **B7 Low, release gating is thin.** A tag is compared only with `CFBundleShortVersionString`. `CFBundleVersion` (37) is not checked to increase, `WHATS_NEW.md` is not checked against the version, and the whole file is attached to every release (`ios.yml:26-30, 131, 152`). **Fix:** check the top heading against the version and publish only the current section.
- **B8 Low, the release job is not pinned.** `ios.yml:116` uses `ubuntu-latest`; Xcode is the runner default; `brew install xcodegen openssl@3` is unpinned (`:32-36`); there is no `concurrency:` key, so overlapping runs can race on `gh release create`. **Fix:** pin `ubuntu-24.04`, select Xcode and the xcodegen version, and add `concurrency: release-${{ github.ref }}`.
- **B9 Low, the FAQ understates data flows.** `docs/index.html:619` says the workflow is "designed to run on-device" and does not name `api.palera.in` or the community anisette servers, both disclosed in `README.md`. **Fix:** name both in the answer.
- **B10 Low, vendored inputs are checked only at download.** `scripts/prepare_dependencies.py`: the built OpenSSL framework and the AltSign tree are accepted whenever their stamps match, so a local change under `vendor/` goes undetected (lines 111, 184-188, 230-232). The patches and `openssl_init.c` have a recorded digest used only as a cache key. Local only, because `vendor/` is gitignored. **Fix:** store the expected digest of the built framework and check it before reuse; pin patch digests in `lock.json`.
- **B11 Low, test setup runs inside `assert()`.** Under `-DNDEBUG` the setup is skipped and the test fails later rather than passing (`scripts/tests/forgesign_resources_test.cpp:13-17`, `forgesign_entitlements_test.cpp:25`, `forgesign_crypto_test.m:12-61`). `scripts/test_signer_resources.sh:8` links Homebrew OpenSSL rather than the pinned framework. **Fix:** move side effects out of `assert`, add `#undef NDEBUG`, and link the vendored OpenSSL.
- **B12 Info, repository hygiene.** Three `ForgeSign-2.4-*.ipa` files sit in the repo root. `build/` holds several IPAs, which `*.ipa` keeps untracked but a force-add would publish. `SimulatorSlimmer/` is an untracked nested repository. Thirteen tracked files are modified and uncommitted, including the bridge header change, so the working tree is not what CI and the docs describe. **Fix:** tidy before the next release; nothing was deleted in this pass.

## Checked and clean

- **Zip extraction:** rejects absolute, drive and `..` paths and symlinks or devices; duplicate names are rejected; extraction cleans up on failure.
- **Overwrites:** `moveItem` refuses to replace; outputs use unique names; `FileCopyOperation` writes atomically with `O_EXCL`; dylib injection refuses to overwrite.
- **Integer and bounds checks:** division and subtraction are guarded; DER reads are bounds-checked.
- **Swift:** no force unwraps or `try!` in the in-scope files; all observable services are `@MainActor`.
- **Memory:** no IPA is read whole; icons are downsampled; downloads stream to disk.
- **Install server:** loopback bind; fixed routes only, no path traversal; no TLS trust overrides; no logging of responses.
- **Credentials:** the Apple password is not persisted; the 2FA code is cleared on submit and cancel; P12 files use complete file protection; P12 passwords and the team certificate are in the Keychain as `WhenUnlockedThisDeviceOnly`.
- **Repositories:** HTTPS only, with userinfo and fragments rejected; redirects re-validated; catalogs capped at 25 MB and icons at 2 MB; filenames sanitised.
- **CI:** all action references are full-SHA pinned and match their version comments; top-level permissions are `contents: read`; no secrets are referenced; the trigger is `pull_request`, not `pull_request_target`.
- **Versions and links:** Info.plist, WHATS_NEW, README and the site all say 2.8.6 (build 37); download links point at `releases/latest/download/ForgeSign-latest.ipa`.
- **Swift tests:** every `@Test` contains an `#expect` or `#require`; none are disabled.

## Not verified

- Anything on a device: signing a real IPA with an extension, OTA installation, and the output of a refresh.
- Apple sign-in, 2FA, and the AltServer and anisette network paths beyond the code reading.
- Whether iOS accepts an `http://` loopback package URL, and ATS coverage of IP-literal hosts.
- The upstream zsign Mach-O load-command copies (`archo.cpp:777, 815`).
- The refresh executor: no caller of `markRefreshed` exists in the tree, so overwrite-on-refresh was not exercised.
- Rendering and VoiceOver output (no simulator screen run).
