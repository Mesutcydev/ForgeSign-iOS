# ForgeSign iOS audit — 8 November 2026

Scope: the iOS signer's SwiftUI app, import and storage lifecycle, provisioning
plan, OTA installation, repository inputs, native resource hashing, tests and CI.
Existing working changes were preserved. The macOS app and AltServer experiment
were outside the final scope. The follow-up includes production build validation and a separately signed
audit app installed on the authorized test device. A full manual signing/OTA round trip was completed. Apple Account
authentication remains unverified.

## Fixed

| Priority | Finding | Result |
| --- | --- | --- |
| P1 | Clean launches could remain blank with the iOS 27 SDK because Info.plist did not declare the scene lifecycle; hosted tests masked the missing configuration. | Added the SwiftUI scene manifest with multiple scenes disabled to preserve one owner of signing/install state. Added a manifest regression and verified a clean launch. |
| P1 | Staging removed the destination before copying. Reopening an already staged file could delete the source; failed replacements destroyed the previous input. | Same-file and symlink aliases are preserved. Replacement copies finish before atomic promotion; failed imports keep the previous selection. Staging is confined to its own directory. |
| P1 | Imports could replace or prune files while inspection, provisioning or signing was using them. | The service rejects staging during active work; UI controls lock and incoming requests wait until it finishes. Cold-start Open In requests are consumed on appearance, and incoming files select Sign. |
| P1 | Manual signing could start while preflight was incomplete or had failed; root profile blockers were ignored. | Pending/failed/encrypted preflight blocks signing with a reason. All bundle audit blockers, including expired certificates, stop the run before native signing. |
| P1 | A valid audited root profile could be accompanied by the unrelated selected profile, causing unnecessary asset-validation failure. | Signing uses only the profiles selected by the audit. The unreachable inspection-free fallback and misleading manual-fallback UI were removed. |
| P1 | Resource hashing treated failed mappings like empty resources, ignored hash failure during sealing, and the fallback file reader could claim success after a short read. | Backported the upstream unreadable-resource fix. Failed hashes stop sealing; file reads check seeks, actual bytes read and I/O errors. Genuine empty resources still hash correctly. |
| P2 | Cancelling or relaunching after an OTA attempt could leave a Library row permanently installing. | Cancellation and silent abort restore the verified copy to signed; interrupted attempts recover on load. Delivered copies keep their delivered state. |
| P2 | Installation begun from Library lacked visible cancellation/retry controls there. | Library now shows the current phase, detailed status, Cancel and Retry as applicable. |
| P2 | The manifest validator accepted missing version metadata and additional install items/packages. | A manifest must bind exactly one item and package, plus the expected bundle and version. |
| P2 | Repository versions bypassed filename sanitization; download calls could overlap programmatically. | Names and versions produce a single bounded filename; an active download or pending handoff prevents a second download. HTTPS validation errors now say HTTPS. |
| P2 | Custom switches were hidden from accessibility and surfaced as static text; form fields lacked explicit labels. | Native Toggle controls expose state/actions. Inputs have labels. Buttons can grow vertically. Theme fonts follow Dynamic Type; form/value and file/asset rows stack at accessibility sizes. The two duplicated certificate/profile rows now share one component. |
| P2 | The initial audit replaced shared clear glass with frosted material, visibly flattening cards and controls. | Restored the original clear Liquid Glass and role-specific optical opacity on iOS 26+. Older systems use ultra-thin material. Reduce Transparency gets a solid surface; Increase Contrast uses native regular glass at full strength. |
| P3 | Unused glass roles, container and shimmer code added maintenance and continuous animation. | Removed unused rendering code and the signing shimmer. The native progress indicator remains; press animation respects Reduce Motion. Removed an unused anisette response binding. |

An empty P12 password is now accepted by the workflow; the native asset validator
still checks it. The input says “If set”.

## Current upstream developments

- **iOS 27 requires the scene lifecycle for apps built with its SDK.** ForgeSign
  already uses SwiftUI App/WindowGroup, but its supplied Info.plist omitted the
  scene manifest. Adding the manifest is necessary for clean launches with the
  current SDK; hosted test startup alone was insufficient evidence. [Apple's
  migration guidance](https://developer.apple.com/documentation/uikit/transitioning-to-the-uikit-scene-based-life-cycle).

- **OpenSSL 3.5.9 LTS replaces the unsupported 3.0.16 binaries.** Source archives
  and all AltSign subdependencies are checksum-pinned. The bootstrap builds one
  shared framework used by both signing engines, with built-in default and legacy
  providers. The 3.5 branch is supported through April 2030. The old static
  libraries and headers were removed. [Official downloads](https://openssl-library.org/source/),
  [release strategy](https://openssl-library.org/policies/releasestrat/).
- **zsign 1.1.3 was released on 20 October 2026.** Its unreadable-resource fix
  applies directly to this fork and was backported. The fork already writes
  matching nested profiles before resource sealing, the issue addressed by
  upstream 1.1.2. A full vendor replacement still needs a deliberate comparison
  against ForgeSign's archive, profile, entitlement and identity patches.
  [Official releases](https://github.com/zhlynn/zsign/releases),
  [resource-hashing fix](https://github.com/zhlynn/zsign/pull/413/files).
- **AltSign authentication work remains branch-specific.** The existing local
  GSA patch corresponds to recent upstream work on AuthKit identity, fresh
  connections and transient-error handling. PR #53 was open when checked; it is
  not a released guarantee that authentication works. Preserve the deliberate
  pre-Marketplace authentication-enabled pin until a replacement is tested with
  a real account, 2FA and certificate reuse. [Upstream proposal](https://github.com/rileytestut/AltSign/pull/53).
- **Apple's current guidance favors native adaptive glass and accessibility.**
  Regular glass provides adaptive legibility, while glass is primarily for
  navigation/controls rather than content cards. Current platform refinements
  apply automatically to native glass. The follow-up preserves ForgeSign’s clear
  glass styling and calibrated opacity, with separate accessibility overrides,
  and keeps the iOS 16 deployment target. A blanket Observation migration would
  require changing that compatibility decision. [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/),
  [WWDC26 platform update](https://developer.apple.com/videos/play/wwdc2026/102/).

## Follow-up work

- Built OpenSSL 3.5.9 from verified source for iOS and host simulator/macOS slices.
  Replaced recursive package clones and scheme-time mutation with a local pinned
  AltSign bootstrap. Both engines link one embedded framework. The AltSign P12
  parser now rejects failed parses safely and releases the key/certificate.
- IPA downloads enforce their 2 GiB budget before every write, reject oversized
  headers and mismatched catalog sizes, expose byte progress and Cancel, and
  remove partials on failure, cancellation and relaunch. Existing destinations
  cannot be truncated. Icons use bounded HTTPS transfers, validate redirects and
  downsample to 256 pixels before decoding.
- Large input and original-retention copies run on a utility queue with byte
  progress, cancellation and atomic replacement. A failed copy keeps the previous
  input. A value-based SigningRequest snapshots the run; SigningWorker owns native
  signing, injection, verification and output promotion away from ContentView.
- Certificate, profile, Library and source rows adapt to accessibility text sizes;
  long names can wrap. Certificate/profile imports use SwiftUI's native file
  importer to avoid losing the presenting sheet and its temporary selection.
- The live test exposed a null call to the new, weak-linked Date `<=` operator
  on an earlier iOS 27.2 beta. Expiry checks now compare time intervals, keeping
  the existing semantics without requiring that newer runtime symbol. Native
  Mach-O page hashes were checked and matched for the app and both frameworks.
- The OTA test reproduced a local HTTP race: Darwin’s accepted sockets inherited
  the listener’s nonblocking mode, so a request arriving after accept was closed
  with EAGAIN. Workers now use blocking sockets with read/write timeouts, retry
  interrupted syscalls and close abandoned sockets. Delayed-header and ranged-IPA
  integration tests cover the real transport. Install failures name the failed
  step, and remote manifests use the validated HTTPS redirect policy.
- Restored clear glass across shared cards, badges and controls after the user
  identified a visual regression in the first audit. Native switches, labels,
  Dynamic Type and reduced-motion behavior remain.

Remaining validation: Apple Account login/2FA and certificate reuse, and signing
an extension-bearing IPA with matching extension profiles on a registered device.
Both need an Apple Account; profile parsing and matching for a real app and its
share extension are covered below. Manual signing, verification, OTA delivery,
actual installation and launch were observed on the registered iPhone.
The Library correctly retained its “delivered” transport milestone; installation
was confirmed independently through device app metadata and launching the sample.

## Verification

- Baseline: 52 simulator tests passed before edits.
- All 79 final simulator tests passed, including streamed transfer limits, prompt
  cancellation, atomic background copies, abandoned-download cleanup, delayed HTTP
  headers, ranged IPA transfers and cancellation during an active transfer.
- All 6 Python IPA packaging tests passed.
- Native identity, entitlement, resource-hashing and file-read checks passed.
- The actual generated production project builds Release with AltSign and OpenSSL
  3.5.9; the earlier isolated-harness and recursive-submodule blockers are resolved.
- The generated macOS framework passed modern AES and legacy RC2/3DES P12 imports,
  wrong-password/malformed input handling, patched AltSign P12 roundtrips, and CMS
  signature verification.
- Native bridge signing and verification succeeded with the authorized local
  P12/profile. A separately named ForgeSign Audit app was installed and launched
  on the profile's registered physical iPhone, under a previously unused bundle
  ID. The two existing ForgeSign app installations were preserved.
- Live manual round trip passed: certificate/profile import, sample preflight,
  signing on-device, independent exported-IPA verification, OTA from Library,
  system Install prompt, and actual launch of ForgeSign Sample 1.0 (1). The
  sample used the audit-only bundle ID. Both original ForgeSign installations
  were compared before/after and remained unchanged. The sample and its imported
  test assets were removed, then the clean final audit app was restored.
- The delayed-header HTTP integration test failed before the socket correction
  (broken pipe), then passed with the fix. The full final suite passed afterward.
- UI: inspected Sign and its accessibility tree, confirmed an interactive native
  switch changes value, and compared stable light-mode screenshots (3.19% pixel
  difference in the first comparison, primarily controls and supporting text).
  A clean restart after the scene-manifest fix displayed the Sign screen.
  Largest-text checking confirmed font scaling and exposed narrow asset columns,
  which were replaced with a shared stacked layout. A clean restart at the largest
  accessibility size then passed: IPA, Certificate and Provisioning profile each
  displayed their value below the label. The original simulator text size was
  restored.
- Follow-up visual checks confirmed clear-glass Sign, Sources and Library surfaces
  in light/dark appearances. The populated certificate/profile pickers were also
  inspected at the largest accessibility size.
- iPad QA covered Sign, Sources and Library on a 13-inch iPad in portrait, in
  landscape, in both appearances and at the largest accessibility text size. It
  found scrolling content unconstrained: on a 1366-point landscape iPad every row
  stretched the full width, leaving each label and its control about a thousand
  points apart. The three scroll roots now cap their content at a readable 700
  points and centre it, which is under any iPhone width and so leaves the phone
  layout unchanged. All three tabs were re-checked afterwards in both appearances.
- ForgeSign's own profile parser and provisioning matcher were run over real
  Apple-issued App Store profiles for an app and its share extension. Each parsed
  to its own concrete application identifier, team, embedded certificates and
  expiry, and the audit matched each nested bundle to its own profile. The app
  profile alone left the extension blocked as missing rather than reusing the app
  profile for it, and an extension profile alone could not stand in for the app.
- Info.plist passed plutil validation; git diff --check passed. Vendored C/C++
  conversion warnings and current SDK test-runtime deployment warnings remain.

CI now bootstraps verified dependencies and runs native crypto, signing, packaging
and simulator checks. The local changes were not committed or published. No
Apple Account sign-in or certificate creation/revocation was performed. The local
signing assets were used only for the authorized separate audit app.
